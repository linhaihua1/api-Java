# 06 - 系统适配指南

## 一、什么是系统适配

不同 web 系统对接口的表达方式差异很大：

| 差异点 | 系统 A | 系统 B |
|---|---|---|
| 认证 | Bearer Token | Cookie 会话 |
| 成功判定 | `body.success == true` | `body.code == "0000"` |
| 域名 | 单域名 | 网关 + 多服务 |
| 编码 | UTF-8 | GBK |
| 报文格式 | JSON | XML |
| 签名 | MD5 + 时间戳 | 无 |

框架把这些差异全部收敛到一份**系统适配档案**（`config/systems/<名>.ini`），换系统时只需切换或新增档案，**不改一行代码**。

## 二、6 种响应判定风格

在档案的 `[response]` 段通过 `style` 指定：

> 6 种风格名均以常量定义于 `com.amsapi.common.Constants`（`STYLE_STATUS` / `STYLE_CODE` / `STYLE_SUCCESS` / `STYLE_ERRNO` / `STYLE_RETCODE` / `STYLE_RAW`），代码中统一引用常量。

| style | 判定路径 | 成功值（默认） | 适用场景 |
|---|---|---|---|
| `status` | `body.status` | （用例提供 expected） | 直接返回状态的系统 |
| `code` | `body.code` / `body.retCode` | （用例提供 expected） | 最常见的 code 风格 |
| `success` | `body.success` / `body.ok` | `true, 1, yes, ok` | 返回布尔标志的系统 |
| `errno` | `body.errno` / `body.errCode` | `0, 200` | C 风格错误码 |
| `retcode` | `body.retCode` / `body.retcode` | `0000, 0, 200, success` | 银行/金融系统 |
| `raw` | （不检查业务码） | — | 只看 HTTP 状态码 |

### 示例

```ini
# 商城系统：success 风格
[response]
style = success
http_ok = 200,201,204
```

```ini
# 银行系统：retcode 风格
[response]
style = retcode
success_path = body.retCode
success_values = 0000,SUCCESS
message_path = body.retMsg
```

```ini
# 政务系统：errno 风格（含自定义路径）
[response]
style = errno
success_path = body.data.errno
success_values = 0
```

### 自定义成功判定路径

如果系统的成功字段不在默认路径，可通过 `success_path` 指定：

```ini
[response]
style = code
success_path = body.result.status_code
success_values = 0
```

## 三、7 种认证策略

在档案的 `[auth]` 段通过 `type` 指定：

### 3.1 none — 无认证

```ini
[auth]
type = none
```

### 3.2 basic — HTTP Basic

```ini
[auth]
type = basic
username = admin
password = 123456
```

### 3.3 bearer — Bearer Token（含 JWT）

```ini
[auth]
type = bearer
token = ${token}          # 支持 ${var}，从变量池取值
header = Authorization     # 默认 Authorization
prefix = Bearer            # 默认 "Bearer "
```

### 3.4 header — 自定义请求头

```ini
[auth]
type = header
header = access-ticket     # 自定义头名
token = ${ticket}
prefix =                    # 前缀（可空）
```

### 3.5 apikey — API Key

```ini
[auth]
type = apikey
key_name = X-Api-Key
token = your-api-key-here
key_in = header            # header 或 query
```

### 3.6 cookie — 会话 Cookie

```ini
[auth]
type = cookie
cookie_string = "JSESSIONID=abc123; token=xyz"
```

或：
```ini
[auth]
type = cookie
cookies = {"JSESSIONID": "abc123", "token": "xyz"}
```

### 3.7 oauth2 — OAuth2 客户端模式

```ini
[auth]
type = oauth2
token_url = http://auth-server/oauth2/token
client_id = your-client-id
client_secret = your-secret
scope = read write
auth_mode = post           # post（参数方式）或 basic（Basic 认证方式）
header = Authorization
prefix = Bearer
timeout = 10
verify = false
refresh_ahead = 60         # 到期前60秒自动刷新
```

## 四、多域名（网关 + 微服务）

很多系统有网关层和多个微服务，通过 `[hosts]` 段定义别名：

```ini
[hosts]
gateway = http://gateway.mall.com
user = http://user-service.mall.com
order = http://order-service.mall.com
goods = http://goods-service.mall.com
```

用例中通过 `host` 字段或 URL 前缀指定：

```yaml
# 方式1：host 字段
- url: /v1/orders
  host: order

# 方式2：URL 内联别名
- url: order:/v1/orders
```

## 五、报文格式与编码

```ini
[env]
encoding = GBK                # 留空=自动探测；指定如 GBK、UTF-8
content_type = application/json
response_format = auto        # auto / json / xml / text
```

- `response_format = xml` — 响应自动解析为 Map（XML → Dict）
- `response_format = text` — 响应作为纯文本，不做 JSON 解析
- `encoding = GBK` — 强制使用 GBK 解码响应

## 六、请求/响应钩子

钩子用于处理签名、时间戳、加解密等协议层需求。

### 6.1 内置钩子

框架提供了几个内置钩子工厂：

| 钩子 | 说明 |
|---|---|
| `com.amsapi.common.hooks.Hooks.makeTimestampNonceHook` | 注入时间戳和随机数 |
| `com.amsapi.common.hooks.Hooks.makeSignHook` | 对参数排序后签名 |
| `com.amsapi.common.hooks.Hooks.makeAesHook` | AES 加密请求字段 |
| `com.amsapi.common.hooks.Hooks.makeDecryptResponseHook` | 解密响应字段 |
| `com.amsapi.common.hooks.Hooks.makeTokenResponseHook` | 从响应提取 token |

### 6.2 在档案中声明

```ini
[hooks]
before_request = com.amsapi.common.hooks.Hooks.makeTimestampNonceHook({"fields":["timestamp","nonce"],"ts_unit":"s"}),com.amsapi.common.hooks.Hooks.makeSignHook({"field":"sign","alg":"md5"})
after_response =
```

### 6.3 自定义钩子

实现一个返回 `Function<Map<String,Object>, Map<String,Object>>` 的静态方法：

```java
public class MyHooks {
    public static Function<Map<String, Object>, Map<String, Object>> addCustomHeader(Map<String, Object> kwargs) {
        return ctx -> {
            Map<String, String> headers = (Map<String, String>) ctx.get("headers");
            headers.put("X-Custom", "value");
            return ctx;
        };
    }
}
```

在档案中引用：
```ini
[hooks]
before_request = com.example.MyHooks.addCustomHeader({})
```

## 七、切换系统的完整示例

### 场景：测试环境切换到商城系统

1. 创建档案 `config/systems/mall.ini`（已提供示例）
2. 运行时指定：

```bash
AMSAPI_SYSTEM=mall \
AMSAPI_BASE_URL=http://gateway.mall.com \
AMSAPI_DATA_SOURCE=yaml \
mvn test -Dtest=TestYamlDriver
```

### 场景：新增一个政务系统档案

```ini
# config/systems/gov.ini
[system]
name = 政务系统
description = Cookie 认证 + errno 风格 + GBK 编码

[env]
base_url = http://gov.test.com
encoding = GBK

[response]
style = errno
success_values = 0

[auth]
type = cookie
cookie_string = "JSESSIONID=${session_id}"
```

运行：
```bash
AMSAPI_SYSTEM=gov AMSAPI_DATA_SOURCE=yaml mvn test
```

## 八、查看当前系统适配信息

启动时日志会打印适配信息：
```
【适配】加载系统档案：mall（商城 / 购物）
系统适配信息: {判定风格=success, 认证方式=bearer, 域名别名=gateway,user,order,goods, ...}
```
