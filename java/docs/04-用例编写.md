# 04 - 用例编写指南

## 一、两种用例编写方式

框架支持两种数据驱动方式，测试人员可根据团队习惯选择：

| 方式 | 文件 | 适合人群 | 优点 | 缺点 |
|---|---|---|---|---|
| YAML | `data/cases/*.yaml` | 开发人员 | 可读性好、版本管理友好 | 不适合非技术人员 |
| Excel | `data/api_tables.xlsx` | 业务/测试人员 | 可视化编辑、可批量 | 需要维护 Excel 文件 |

切换方式：`AMSAPI_DATA_SOURCE=yaml|excel|all`

## 二、YAML 用例编写

### 2.1 文件结构

```yaml
cases:                      # 固定字段，用例列表
  - id: 1001                # 用例ID（唯一，用于依赖引用）
    title: 登录并提取票据    # 用例标题（报告中展示）
    tags: [ smoke ]         # 标签（用于冒烟筛选）
    url: /v1/users/login    # 接口路径（支持相对/绝对/域名别名）
    method: get             # HTTP 方法
    headers:                # 请求头（可选）
      Content-Type: application/json
    request_body:           # 请求体（可选）
      username: demo_user
      password: demo_password
    relation: ticket=body.data.ticket   # 关联提取（可选）
    expected_code: 200      # 期望业务码（可选）
    expects: "type:body.data=dict; not_empty:body.data.ticket"  # 断言（可选）
```

### 2.2 完整字段说明

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | 否 | string/number | 用例唯一标识，depends 引用时必填 |
| `title` | 否 | string | 用例标题 |
| `tags` | 否 | list/string | 标签，冒烟筛选用 |
| `url` | 是 | string | 接口地址 |
| `method` | 是 | string | get/post/put/delete/patch/head/options |
| `headers` | 否 | map | 请求头 |
| `request_body` | 否 | map/string | 请求体 |
| `params` | 否 | map | Query 参数 |
| `cookies` | 否 | map | Cookie |
| `content_type` | 否 | string | 覆盖默认 Content-Type |
| `host` | 否 | string | 域名别名（对应档案 [hosts]） |
| `relation` | 否 | string | 关联提取表达式 |
| `expected_code` | 否 | string/number | 期望业务码 |
| `expects` | 否 | string/list | 断言列表 |
| `check_business` | 否 | bool | 是否检查业务成功（默认 true） |
| `setup` | 否 | list | 前置步骤 |
| `teardown` | 否 | list | 后置清理步骤 |
| `depends` | 否 | string | 依赖的用例 id（逗号分隔） |

### 2.3 参数关联（接口间传参）

**场景**：先登录获取 ticket，后续接口携带 ticket。

```yaml
cases:
  # 用例1：登录并提取 ticket
  - id: 1001
    title: 登录
    url: /v1/users/login
    method: post
    request_body:
      username: admin
      password: 123456
    relation: ticket=body.data.ticket

  # 用例2：使用 ticket 查询用户信息
  - id: 1002
    title: 查询用户信息
    depends: 1001
    url: /v1/users/${ticket}/profile
    method: get
```

**关联表达式语法**：`变量名=响应路径`

- `ticket=body.data.ticket` — 提取 body.data.ticket 存入变量 ticket
- `first=body.data.rows.0.name` — 支持列表下标
- `a=body.a,b=body.b` — 多个用逗号分隔

**引用变量**：在 url / headers / request_body 中使用 `${变量名}`

### 2.4 断言（expects）

**简写语法**：`算子:路径=值; 算子:路径=值`

```yaml
expects: "equals:body.code=200; not_empty:body.data; gt:body.data.total=0"
```

**完整写法**（List 形式）：

```yaml
expects:
  - op: equals
    path: body.code
    value: 200
    msg: 状态码应为200
  - op: not_empty
    path: body.data
  - op: type
    path: body.data.list
    value: list
```

**21 种断言算子**：

| 算子 | 说明 | 示例 |
|---|---|---|
| `equals` | 相等 | `equals:body.code=200` |
| `not_equals` | 不等 | `not_equals:body.code=500` |
| `contains` | 包含 | `contains:body.msg=成功` |
| `not_contains` | 不包含 | `not_contains:body.msg=错误` |
| `startswith` | 前缀 | `startswith:body.msg=操作` |
| `endswith` | 后缀 | `endswith:body.msg=成功` |
| `regex` | 正则匹配 | `regex:body.phone=^1\d{10}$` |
| `type` | 类型校验 | `type:body.data=dict` |
| `exists` | 存在 | `exists:body.data.token` |
| `not_exists` | 不存在 | `not_exists:body.error` |
| `in` | 在集合中 | `in:body.status=active,pending` |
| `not_in` | 不在集合中 | `not_in:body.code=500,502` |
| `gt` | 大于 | `gt:body.data.count=0` |
| `ge` | 大于等于 | `ge:body.data.count=1` |
| `lt` | 小于 | `lt:body.elapsed=3000` |
| `le` | 小于等于 | `le:body.elapsed=5000` |
| `length` | 长度 | `length:body.data.list=10` |
| `empty` | 为空 | `empty:body.error` |
| `not_empty` | 非空 | `not_empty:body.data` |
| `elapsed` | 耗时 | `elapsed:=3000` |
| `schema` | JSON Schema | （暂未实现） |

**路径根**：以完整响应为根，常用路径前缀：
- `body.xxx` — 响应体
- `code` — HTTP 状态码
- `headers.xxx` — 响应头
- `elapsed` — 请求耗时

### 2.5 前置/后置步骤

```yaml
cases:
  - id: 2001
    title: 创建订单并清理
    url: /v1/orders
    method: post
    request_body:
      product_id: 100
      quantity: 1
    setup:
      # 前置：先登录获取 token
      - method: post
        url: /v1/users/login
        request_body: { username: admin, password: 123 }
        relation: token=body.data.token
    teardown:
      # 后置：删除测试订单
      - method: delete
        url: /v1/orders/${order_id}
    relation: order_id=body.data.order_id
```

### 2.6 用例依赖

```yaml
cases:
  - id: 1001
    title: 步骤1-登录
    ...

  - id: 1002
    title: 步骤2-查询（依赖1001）
    depends: 1001
    ...
```

如果 1001 失败，1002 自动 skip。

## 三、Excel 用例编写

Excel 文件位置：`data/api_tables.xlsx`，Sheet 名由 `conf.ini` 的 `sheet_name` 指定。

### 3.1 表头定义

第一行为表头，列名与 YAML 字段一一对应：

| 列名 | 说明 |
|---|---|
| id | 用例ID |
| title | 用例标题 |
| tags | 标签（逗号分隔） |
| url | 接口地址 |
| method | HTTP 方法 |
| headers | 请求头（JSON 字符串） |
| request_body | 请求体（JSON 字符串） |
| relation | 关联提取 |
| expected_code | 期望业务码 |
| expects | 断言 |
| depends | 依赖的用例ID |

### 3.2 示例

| id | title | tags | url | method | request_body | relation | expected_code |
|---|---|---|---|---|---|---|---|
| 1001 | 登录 | smoke | /v1/users/login | post | {"username":"admin","password":"123"} | ticket=body.data.ticket | 200 |

## 四、冒烟筛选

```bash
# 只执行 tags 包含 smoke 的用例
AMSAPI_SMOKE=true AMSAPI_TAGS=smoke mvn test
```

或修改 `conf.ini`：
```ini
[run]
smoke = true
tags = smoke
```

## 五、运行用例

```bash
# YAML 用例
AMSAPI_DATA_SOURCE=yaml mvn test -Dtest=TestYamlDriver

# Excel 用例
AMSAPI_DATA_SOURCE=excel mvn test -Dtest=TestExcelDriver

# 全部数据源
AMSAPI_DATA_SOURCE=all mvn test
```
